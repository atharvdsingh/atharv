## The Beginning

What started as inspecting elements in the browser turned into writing my first HTML page, which turned into building my first React app, which turned into... well, this.

I fell in love with the **feedback loop** — write something, see it come alive, break it, fix it, make it better. That cycle is addictive, and it hasn't stopped since.

## What I Build

I work across the entire stack, but my sweet spot is the intersection of **clean backend architecture** and **polished frontend experiences**.

### Frontend
- **React & Next.js** — my primary tools for building fast, SEO-friendly applications
- **TypeScript** — because runtime errors are the enemy
- **Tailwind CSS** — rapid prototyping with pixel-perfect control
- **Framer Motion** — bringing interfaces to life with purposeful animation

### Backend
- **Node.js & Express** — the backbone of most of my APIs
- **PostgreSQL & MongoDB** — choosing the right database for the right problem
- **Redis** — for caching layers that make everything feel instant
- **Docker** — because "it works on my machine" isn't good enough

Here's a quick example of how I typically structure an Express route:

```typescript
import { Router } from "express";
import { authenticate } from "@/middleware/auth";
import { validateBody } from "@/middleware/validate";
import { createPostSchema } from "@/schemas/post.schema";
import { PostController } from "@/controllers/post.controller";

const router = Router();

router.post(
  "/posts",
  authenticate,
  validateBody(createPostSchema),
  PostController.create
);

export default router;
```

Clean. Predictable. Testable.

## My Philosophy

I've learned a few things building software over the years:

1. **Readability beats cleverness** — If your teammate can't understand your code in 30 seconds, rewrite it.
2. **Ship early, iterate fast** — Perfection is the enemy of progress. Get it out there, get feedback, improve.
3. **Architecture matters from day one** — Technical debt compounds faster than you think.
4. **Design is not decoration** — Good design makes software *usable*. Great design makes it *invisible*.
